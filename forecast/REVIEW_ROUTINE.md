# M4 — weekly calibration review Routine

**Status: created and enabled** on 2026-07-31 as trigger
`trig_01T5fCpZdn3im3J1Km178LXd`, named "Weekly calibration review —
nantucket-late-august". First firing 2026-08-03 14:23 UTC. The prompt below is
the text it runs, verbatim; edit the Routine, not just this file, if you change
it.

This must be a **Claude Code Cloud Routine**, not a `/loop` and not a
session-scoped cron job. Both of those live only as long as the session and
expire after 7 days, which makes them useless for a review cadence measured in
months. DESIGN.md §8 rules them out explicitly.

**Schedule:** `23 14 * * 1` — Mondays, 14:23 UTC.

The `:23` is deliberate. Scheduled runs fire up to ~30 minutes after their
nominal time, and the top-of-hour and half-hour slots are where every other
schedule lands. §8 has the full reasoning; for the weekly review the stakes are
low, but the daily job at `:17` shares the rationale and consistency is free.

**Mode:** fresh session per firing. It reads committed state (`CONTEXT.md`,
`DESIGN.md`, git history) and needs no memory of prior runs.

## Prompt

```
Weekly review of the gas-price forecast calibration loop in the repo
`parallax-parking/nantucket-late-august`. You are running autonomously and
cannot ask questions, so everything you need is below. Default to doing
nothing — silence is the correct output most weeks.

## Context

The repo runs a daily GitHub Actions job that scrapes the AAA national average
gas price, scores the previous day's probabilistic forecast, and writes a new
one. The forecast is not the product; the calibration record is.

Read these two files first, in this order:
- `CONTEXT.md` (repo root) — regenerated every run, current state of the system
- `DESIGN.md` (repo root) — the reasoning, the invariants, and §10's list of
  already-rejected ideas

Then check the last ~10 commits and the recent Actions runs of the
`AAA national average` workflow.

## Your job

Open **one** GitHub issue if and only if one or more of the triggers below
fires. If none fires, do nothing at all: no issue, no comment, no PR, no
commit. A quiet week is a healthy week and must not produce noise.

Triggers:

1. **The pipeline stopped.** No new observation row in
   `data/aaa_national_average.csv` for 2+ consecutive calendar days, or the
   workflow's last run failed. Note that GitHub disables scheduled workflows
   after 60 days of repo inactivity — if the daily commits have stopped, check
   for that specifically.
2. **Overconfidence.** `CONTEXT.md` contains the "⚠︎ **Overconfident**" flag,
   meaning residual spread exceeds 1.25× the claimed sigma.
3. **Calibration drift, but only once it means something.** Only if
   `CONTEXT.md` reports `n_eff >= 50` for `mode = model`: the headline `> +0c`
   Brier is worse than 0.25 (i.e. worse than a coin flip), or pooled
   reliability gaps exceed 15 percentage points in more than half the populated
   bins. Below n_eff = 50 this trigger does not exist — do not open an issue
   about numbers the report itself says are not concludable.
4. **Parser degradation.** Price columns arriving blank, revision warnings in
   the run logs (AAA restating a number we already stored), or a `ScrapeError`
   in a failed run.
5. **Regime the model can't cover.** Any single-day change larger than ±5 cents
   in the last week. The model is deaf to news: its worst historical call was a
   +48.5c week predicted at +6.5c, driven by a geopolitical supply shock.
   Momentum is a lagging echo in those periods, not a leading signal. Flag it
   so the calibration record carries the context; do not try to fix the model
   for it.

## Rules

- **Never edit `data/forecasts.csv`.** Forecast rows are immutable once
  written; that immutability is the entire evidentiary basis of the record.
- **Never change the model, the features, or the constants.** If you believe a
  change is warranted, say so in the issue and stop. A human decides.
- **Do not relitigate DESIGN.md §10.** Regional cross-sections, asymmetric
  crude terms, error-correction terms, and gradient boosting were all measured
  and rejected. Proposing them again without new evidence is noise.
- Do not open a second issue for something already covered by an open issue —
  search first, and add a comment to the existing one instead, only if there is
  genuinely new information.

## Issue format

Title: short and specific, e.g. `Calibration: reliability gap 22pp in the
0.7-0.9 bin` — not `Weekly review`.

Body: what triggered it, the specific numbers from `CONTEXT.md` that show it,
the date range involved, and what you recommend. Keep it under ~300 words.
State plainly if you are uncertain whether something is real signal or
small-sample noise.

End every issue body with exactly:
```

## Managing it

The Routine was created with the prompt above, the cron `23 14 * * 1`, and a
fresh session per firing. To change the schedule or the prompt, update the
trigger in place rather than deleting and recreating it — that keeps the run
history. It can also be paused (disabled) without losing anything.

One thing to confirm on the first live firing: the create call warned that the
Routine stores no claude.ai connectors, so its sessions get no `mcp__<server>__*`
connector tools. GitHub access in a Claude Code Cloud session comes from the
environment's repo sources rather than from a connector, so issue-opening is
expected to work — but that is an expectation, not something verified here. If
the first run cannot reach GitHub, recreate the Routine from a session that
holds the needed grants, or from the claude.ai Routines UI.

## When it starts mattering

Trigger 3 is gated at `n_eff >= 50`, which the system will not reach for
months. Triggers 1 and 4 are the only ones that can fire meaningfully in the
first weeks — which is the point: it is on now so that a silent pipeline
failure gets noticed, and it is designed to stay quiet until then.
